[0:00 – 0:40] PART 1: INTRODUCTION & ARCHITECTURE
--------------------------------------------------------------------------------
Visual:
- Browser showing the PaperSpace Dashboard with Alice Johnson logged in.
- Quick switch to VS Code showing project directory structure and ARCHITECTURE.md.

Spoken Script:
"Hello! My name is Hemant Singh, and this is PaperSpace—a lightweight collaborative
document editor inspired by Google Docs, built for the Ajaia AI-Native Full Stack
Assessment.

PaperSpace is built on Next.js 15 App Router, TypeScript, Tailwind CSS, TipTap 2.x,
Prisma 6, and PostgreSQL. The UI was designed and extracted using Google's Stitch
MCP server, adopting clean design tokens for typography, surfaces, and states.

All document authorization is strictly enforced on the server using an RBAC
matrix: returning HTTP 404 for unauthorized documents to prevent UUID enumeration,
and HTTP 403 for insufficient role permissions."

[3:00 – 3:50] PART 5: ROLE-BASED ACCESS CONTROL (RBAC) IN ACTION
--------------------------------------------------------------------------------
Visual:
- Use the Demo Persona Switcher in the top navbar to switch to **Bob Smith (Editor)**.
- Open the document shared by Alice.
- Show: Bob CAN edit the body text, and changes autosave.
- Show: Bob CANNOT rename the document title (title has a lock icon and tooltip).
- Use the Demo Persona Switcher to switch to **Charlie Davis (Viewer)**.
- Open the document shared by Alice.
- Show: Charlie's view is strictly read-only: the toolbar is completely hidden,
  and the editor canvas is locked (`editable: false`).
- Show that an attempt to access a document that isn't shared returns HTTP 404.

Spoken Script:
"Now, let's verify our server-side security.
Using our top-bar persona switcher, I'll switch to Bob Smith, our Editor.
Bob opens the document: he has full permission to edit text in the canvas, and
autosave persists his edits. But notice the title: it's locked with a lock icon.
If Bob attempts to rename or delete the document, the server returns HTTP 403 Forbidden.

Now let's switch to Charlie Davis, our Viewer.
Opening the document, Charlie's toolbar is completely hidden, and the editor is
locked in read-only mode.
Even if a malicious user bypasses the UI and dispatches a PATCH request directly,
our server-side RBAC engine intercepts the call and rejects it with HTTP 403.
And if Charlie attempts to access Alice's private documents, the API returns HTTP 404,
safely preventing UUID enumeration."
